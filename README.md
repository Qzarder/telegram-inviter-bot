# Telegram Inviter Bot

Бот для управления задачей инвайта через Telegram.

## 1) Подготовка

1. Установи Python 3.11+.
2. Установи зависимости:

```bash
pip install -r requirements.txt
```

3. Создай `.env` из шаблона:

```bash
copy .env.example .env
```

4. Заполни в `.env`:
- `BOT_TOKEN`
- `API_ID`
- `API_HASH`
- при необходимости подстрой:
  - `INVITE_BAN_COOLDOWN_HOURS` (по умолчанию 24 часа)
  - `FLOOD_WAIT_EXTRA_SECONDS` (по умолчанию +60 секунд к FloodWait)
  - `APPROVAL_CHECK_INTERVAL` (как часто проверять одобрение заявок в группу, по умолчанию 120 сек)
  - `PROXY_CHECK_INTERVAL` (как часто проверять доступность прокси во время работы, по умолчанию 30 сек)
  - `PROXY_CHECK_TIMEOUT` (таймаут проверки прокси, по умолчанию 8 сек)
  - `SPAMBOT_CHECK_ENABLED` (включить проверку через @SpamBot, по умолчанию true)
  - `SPAMBOT_TIMEOUT_SECONDS` (таймаут ответа @SpamBot, по умолчанию 25 сек)
  - `SPAMBOT_LIMITED_COOLDOWN_HOURS` (отлежка, если @SpamBot показал ограничения, по умолчанию 24 часа)
  - `WARMER_ENABLED` (включить фоновый прогрев, по умолчанию true)
  - `WARMER_SCAN_INTERVAL` (как часто искать новые аккаунты для прогрева, по умолчанию 45 сек)
  - `WARMER_STEP_DELAY_MIN/MAX` (паузы между шагами внутри одного аккаунта)
  - `WARMER_ACCOUNT_PAUSE_MIN/MAX` (пауза между аккаунтами)
  - `WARMER_MANUAL_START_PERCENT` (порог ручного запуска в работу из раздела прогрева, по умолчанию 80)
  - `WARMER_CHANNELS_PER_ACCOUNT` (сколько каналов выбирается на один аккаунт в прогреве, по умолчанию 25)
  - `WARMER_CHANNEL_DISTRIBUTION_DAYS` (за сколько дней распределять прогрев по каналам, по умолчанию 3)
  - `WARMER_MAX_CHANNELS_PER_PASS` (максимум новых каналов за один проход аккаунта, по умолчанию 2)

## 2) Файлы и папки

- `sessions/` — папка с `.session` файлами.
- `targets.txt` — список username, по одному в строке.
- `channels.txt` — список каналов для прогрева.
- Формат `channels.txt`:
  - `indian:username`
  - `russian:username`
  - `global:username`
  - если префикса нет, канал считается `global`.
- `processed_usernames.txt` — создается автоматически, хранит уже обработанных пользователей.
- `saved_target_group.txt` — создается автоматически, хранит сохраненную группу.
- `account_cooldowns.json` — создается автоматически, хранит аккаунты в отлежке.
- `warmer_state.json` — создается автоматически, хранит прогресс прогрева по шагам.

### Сессии по странам

Можно хранить сессии так:

```text
sessions/US/acc1.session
sessions/US/acc2.session
sessions/DE/acc3.session
sessions/KZ/acc4.session
```

Бот возьмет страну из названия папки (`US`, `DE`, `KZ`) и подберет прокси этой страны.

## 3) Гео-прокси по странам

1. В `.env` включи:

```env
USE_PROXY=true
```

2. Создай `proxy_pool.json` на основе `proxy_pool.example.json`.

Пример:

```json
{
  "in": [
    { "type": "http", "addr": "109.236.82.42", "port": 443, "user": "u1", "pass": "p1" },
    { "type": "http", "addr": "109.236.82.43", "port": 443, "user": "u2", "pass": "p2" }
  ],
  "default": [
    { "type": "socks5", "addr": "9.9.9.9", "port": 1080, "user": "u", "pass": "p" }
  ]
}
```

- Для каждой страны можно указать сразу несколько прокси (массив).
- Бот будет чередовать их по кругу автоматически.
- Ключи стран можно писать в любом регистре (`US` или `us`).
- Если для страны нет записи, бот попробует `default`.
- Если нет и `default`, бот использует глобальный прокси из `.env` (если он заполнен).
- Старый формат `country_proxies.json` тоже поддерживается для совместимости.

## 4) Запуск

```bash
python main.py
```

В Telegram:
- `/start`
- `Запустить инвайт`

Если группа уже сохранена, повторно ссылку отправлять не нужно.

## 5) Кнопки управления

- `Запустить инвайт` — старт задачи.
- `Проверить аккаунты` — проверка `.session`, авторизации, доступности прокси и статуса через `@SpamBot`.
- `Восстановить сессии` — запускает авто-восстановление из папки `ACCOUNT_IMPORT_DIR`.
- `Сменить группу` — сохранить новую группу.
- `Статус задачи` — текущий прогресс.
- `Остановить` — мягкая остановка.
- `Статистика` — общая статистика и сохраненная группа.
- `🔥 Прогрев` — список аккаунтов с процентом прогрева и кнопками ручного запуска в работу.

Во время инвайта аккаунты работают по очереди: пока один в паузе, бот переключается на другие.

Перед инвайтом новые аккаунты сначала отправляют заявку на вступление в целевую группу (если нужно), и бот ждет, пока админ одобрит их. Только после одобрения аккаунт начинает инвайтить.

## 6) Отлежка аккаунтов (автоматически)

- Если аккаунт получает ограничение на инвайты (`PeerFlood`) или `FloodWait`, бот сам отправляет его в отлежку.
- Пока срок отлежки не закончился, аккаунт не используется в новых запусках.
- Когда срок проходит, аккаунт автоматически снова участвует в работе.
- Счетчик аккаунтов в отлежке видно в кнопке `Статистика`.

## 7) Защита по прокси

- Перед стартом каждого аккаунта бот проверяет, что его прокси реально доступен.
- Во время задачи бот периодически проверяет прокси заново.
- Если прокси отвалился, бот делает экстренную остановку всей задачи, чтобы не рисковать аккаунтами.

## 8) Проверка через @SpamBot

- Перед стартом аккаунта в инвайте бот может проверить ограничения через `@SpamBot`.
- Если у аккаунта есть ограничения, он автоматически пропускается и уходит в отлежку.

## 9) Фоновый прогрев (warmer)

- Запускается вместе с `main.py` автоматически.
- Не повторяет уже сделанные действия: шаги сохраняются в `warmer_state.json`.
- Для новых аккаунтов прогрев идет полностью по циклу (аватар, контакт, каналы/чтение).
- Новые `.session`, добавленные в папку `sessions`, подхватываются автоматически без перезапуска бота.
- Когда идет инвайт или ручная проверка аккаунтов, warmer ставится на паузу и продолжает потом.
- Аккаунт с 100% прогрева автоматически получает статус `Уже в работе` и участвует в инвайте.
- Аккаунт с прогревом от `WARMER_MANUAL_START_PERCENT` можно вручную пустить в работу кнопкой из раздела `🔥 Прогрев`.
- Для каждого аккаунта каналы выбираются рандомно из `channels.txt` с сохранением пропорции подписок:
  - `global` — 25%
  - `russian` — 15%
  - `indian` — 60%
- Подписки в каналы теперь идут не залпом: бот распределяет их на `WARMER_CHANNEL_DISTRIBUTION_DAYS` дней.

## 10) Авто-восстановление session без ручной возни

Добавлен скрипт: `session_recover.py`.

Он умеет автоматически пытаться собрать рабочий `Telethon .session` из:
- `*.session` (прямая проверка)
- `*.session` в формате sqlite (часто pyrogram, пробует конвертацию)
- `*.json` (ищет `session_string`/`telethon_string` и т.п.)
- `tdata` (если установлен `opentele`)

### Как подготовить папку

Создай, например, `account_import/`, а внутри — подпапки по аккаунтам.

Пример:

```text
account_import/
  IN/
    acc_1/
      tdata/
      account.session
      data.json
    acc_2/
      pyrogram.session
  RU/
    acc_3/
      227157428_telethon.session
```

Если есть вложенность по странам (`IN`, `RU`), скрипт положит результат в `sessions/IN/...` и `sessions/RU/...`.

### Запуск

```bash
python session_recover.py --source account_import
```

Опции:
- `--force` — перезаписать уже существующие `.session`
- `--use-proxy` — проверять валидность через прокси из `.env`

Важно:
- скрипт не может «взломать» аккаунт; он восстанавливает только из уже существующих данных входа;
- если бот сейчас запущен, лучше остановить его перед восстановлением, чтобы не словить `database is locked`.
